Part 1: Ray Generation and Scene Intersection

In generate_ray, I constructed a ray that started from the camera position and intersects the given coordinate (x,y). I first started by converting the x and y coordinates to normalized camera space usign the equation \[x_{camera} = (2x-1)\tan\left(\frac{hFov}{2}\cdot\frac{\pi}{180}\right)\] for x, and repeating the same for y. I set z to -1 as that is considered the center from the camera's perspective. Finally, I converted the coordinates back to world space by multiplying them by c2w, the given camera-to-world rotation matrix. I constructed the ray setting its d value to the resulting coordinates, its o value to the given camera position pos, its min_t to the given value nClip and finally its max_t to the given value fClip.
In raytrace_pixel, I take the input coordinate (x,y) and set its corresponding radiance in the samplebuffer. This is done by sampling num_samples times, generating a ray, keeping track of their illumination by summing up their est_radiance_global_illumination value, and finally dividing the resulting sum by the number of samples to estimate their integral. I update the pixel (x,y) in the sample buffer to this integral estimate.
To compute the ray-triangle intersections, I use the Moller-Trombore algorithm, which sets the ray equation \[\mathbf{o}+t\mathbf{d}\] equal to the triangle's barycentric equation \[(1-u-v)\mathbf{p}_1+u\mathbf{p}_2+v\mathbf{p}_3\] :
\[(\mathbf{o}+t\mathbf{d} = 1-u-v)\mathbf{p}_1+u\mathbf{p}_2+v\mathbf{p}_3\]
By solving for t with this equation, we can check if the ray intersects with the triangle by checking if the resulting t-value is between the ray's max_t and min_t. In the triangle intersect method, I repeat this same moller-trumbore process for determining if the ray intersects with the triangle, and then I further set the resulting intersection's member variables to save the resulting t value, the unit vector of the barycentric equation (1-u-v)p_1 + (u)p_1 + (v)p_2, the primitive to the triangle, and the bsdf to the triangle's bsdf. The information is used by the rendering pipeline to determine the lighting at the intersection point.

Part 2: Bounding Volume Hierarchy

I used a recursive algorithm to construct the BVH. The base case was that if the distance between the start and end primitive was less than or equal to max_leaf_size, then I return the BVH node with its start and end variables set to the start and end primitive respectively, and the right and left children set to null. If there are still more primitives than max_leaf_size, then I set the axis to split based off which one has the greatest distance between start and end. The heuristic I chose for the splitting point was taking the average of the primitives across the chosen axis. This was done by iterating through all of the primitives from start to end, adding their corresponding axis values, dividing by the number of primitives, and setting it as the split point. Finally, I set the node's left and right pointers by calling construct_bvh(start, splitpoint, max_leaf_size) and construct_bvh(splitpoint, end, max_leaf_size) respectively. To account for infinite recursion, I check to see if the splitpoint is equal to either the start or the end pointer, and if so I reset the splitpoint to \[start + count / 2\].

As shown with the results below, using BVH acceleration significantly improves the rendering speed. The smallest difference between the before and after BVH rendering time was with cow.png, which was around 53 seconds faster. The largest difference was with maxplanck.png, which took 10 minutes without BVH and 0.05 seconds with BVH. BVH is able to improve the render time by hierarchically organizing the bounding boxes and reducing the amount of intersection tests between the ray and primitives that need to be run. This shows that the more complex an image is to render, the more impactful using BVH is. The improvement may not be as noticeable with simple images but will be very useful for more complicated images.

Part 3: Direct Illumination

To implement zero bounce radiance, I simply return the bsdf emission value of the passed in perimeter. To implement one bounce radiance, I return either hemisphere or importance sampling direct lighting based on the direct_hemisphere_sample variable. To implement hemisphere-sampling direct lighting, we are first given variables to help transform the object space to world space (o2w) and vice versa (w2o), the vector hit point where the intersection occurs (hit_p), the outgoing direction from the intersection point (w_out), and the number of samples (num_samples). For each sample, I use hemisphereSampler->get_sample(), saving it to variable wi, and convert the samples to world space with o2w. I then create a ray starting from the hit point in the direction of the hemisphere sample distance. If the created ray intersects with anything, I calculate the estimate \[ \frac{f_r(p, \omega_j \rightarrow \omega_r) L_i(p, \omega_j) \cos\theta_j}{p(\omega_j)}\] by setting L to the object's radiance with bsdf->get_emission(), setting f to the intersection's diffuse bsdf value with bsdf->f(w_out, wi), setting the sample's z value wi.z as cos since wi's surface normal is aligned with the positive z axis, and finally setting p to 1/(2*pi) as the hemisphere is sampled uniformly. I sum each of the resulting values per sample, and divide by num_samples to calculate the final value of hemisphere direct lighting.
To implement importance-sampling direct lighting, I follow a similar process to hemisphere lighting. However rather than just iterating through the range of num_samples, I repeat that loop for every light in the scene. If the light is a point light source, then only one sample is taken, and otherwise ns_area_light samples are taken. I create the ray starting from the hit point in the direction of the sampled light. If the created ray intersects with anything, I calculate the estimate with equation above. I set L to the light's radiance using sample_L(), which also populates the sample direction vector wi, the distance distTolight between wi and the hitpoint, and the probability density funciton pdf. I set f to the intersection's bsdf value with bsdf->f(wo, wi_local), where wi_local is wi converted from world to object space, and I set cos equal to wi_local.z. I set p equal to pdf, which was populated earlier with sample_L(). Finally, after summing up the resulting values for each light, I divide by the amount of lights in the scene.

As shown with the photos above, using importance sampling over uniform hemisphere sampling can lead to cleaner, noise-reduced renderings. This is due to the fact that importance samplings are capable of dedicating more resources to more complex portions of the image, allowing such portions to look cleaner and smoother. When light comes from a small, single source as seen in the cornell box, or when there are a limited number of samples that can be used, the impact of importance sampling is more noticeable. Importance sampling will take more samples in areas where light is concentrated, which is more likely to be on emissive surfaces. In contrast, hemisphere sampling will uniformly distribute rays which are not as likely to intersect the light source, especially in an image where the light only comes from one small source.

Part 4: Global Illumination

To implement indirect lighting, I recursively called the one_bounce_radiance and at_least_once_bounce_radiance. The base case is when the given ray's depth is at 0, to which we just return the 0 vector L_out. If we are accumulating bounces and the ray's depth is equal 1, then we call one_bounce_radiance and pass in the given ray and intersection, and add the result to L_out. Otherwise, we check the ray if it intersects with anything, and if so then we set L by calling at_least_one_bounce_radiance with the resulting intersection, calculate the same value given by the equation in part 3 with f set with bsdf->sample_f which gets a random incoming ray sample and returns its corresponding diffuseBSDF value, add it to L_out and return it. With russian roulette implemented, if the coin flip returns within the given probability then we return before checking for any intersections. Finally, we update est_radiance_global_illumination to return the result of zero_bounce_radiance + at_least_one_bounce_radiance.


When setting the max depth to 2 and 3 (2nd and 3rd bounce), the shading is more complex and you can see the colors of the cornell box walls reflected on the bunny (color bleeding). This is because rather than only having 0-1 bounces from the original light source, the additional bounces can capture more extensive indirect illumination from the surrounding surfaces. This contributes to the quality of the image rendering as it has more realistic lighting dynamics when it comes to color and illumination. In more complex environments with varying colors and light sources, using global/indirect illumination is powerful as it can factor in more than just the first light source bounce.


Part 5: Adaptive Sampling

Adaptive sampling is a way to intuitively distribute samples to image areas with higher variance or rendering difficulty, rather than using the same amount of samples for every pixel. To do this, at every sample we keep track of the current sum and squared sum of illuminance using est_radiance_global_illumination() and illum(). Then, with those sums we check every samplesPerBatch pixel's illuminance mean and variance up to that point, and calculate the value I with \[I = \frac{1.96\sigma}{\sqrt{n}}\] where \[\sigma\] is the estimated standard deviation of the sampled illuminance values and (n) is the number of samples taken so far. If I is less than or equal maxTolerance * mean, this means that we are sufficiently confident that the pixel has converged and can break out of the ray tracing loop early. Finally, rather than always dividing the integral estimate by num_samples I keep track of the samples used in the case that tracing is stopped early, and divide by that amount instead.
