Overview

In this homework, I worked on implementing several techniques for ray tracing and path tracing. I set up methods to construct rays, bounding boxes, and acceleration structures (BVH), as well as methods for intersections and illumination/shading. The time it took to complete this homework was longer than the previous two homeworks, and I learned that there were several edge cases and variables that I had to account for when it came to path tracing. I found the adaptive sampling most interesting as it was nice to see how the sample rate images populated themselves and it also contributed to smoother photos.

Part 1: Ray Generation and Scene Intersection

In generate_ray, I constructed a ray that started from the camera position and intersects the given coordinate (x,y). I first started by converting the x and y coordinates to normalized camera space usign the equation \[x_{camera} = (2x-1)\tan\left(\frac{hFov}{2}\cdot\frac{\pi}{180}\right)\] for x, and repeating the same for y. I set z to -1 as that is considered the center from the camera's perspective. Finally, I converted the coordinates back to world space by multiplying them by c2w, the given camera-to-world rotation matrix. I constructed the ray setting its d value to the resulting coordinates, its o value to the given camera position pos, its min_t to the given value nClip and finally its max_t to the given value fClip.
In raytrace_pixel, I take the input coordinate (x,y) and set its corresponding radiance in the samplebuffer. This is done by sampling num_samples times, generating a ray, keeping track of their illumination by summing up their est_radiance_global_illumination value, and finally dividing the resulting sum by the number of samples to estimate their integral. I update the pixel (x,y) in the sample buffer to this integral estimate.
To compute the ray-triangle intersections, I use the Moller-Trombore algorithm, which sets the ray equation \[\mathbf{o}+t\mathbf{d}\] equal to the triangle's barycentric equation \[(1-u-v)\mathbf{p}_1+u\mathbf{p}_2+v\mathbf{p}_3\] :
\[(\mathbf{o}+t\mathbf{d} = 1-u-v)\mathbf{p}_1+u\mathbf{p}_2+v\mathbf{p}_3\]
By solving for t with this equation, we can check if the ray intersects with the triangle by checking if the resulting t-value is between the ray's max_t and min_t. In the triangle intersect method, I repeat this same moller-trumbore process for determining if the ray intersects with the triangle, and then I further set the resulting intersection's member variables to save the resulting t value, the unit vector of the barycentric equation (1-u-v)p_1 + (u)p_1 + (v)p_2, the primitive to the triangle, and the bsdf to the triangle's bsdf. The information is used by the rendering pipeline to determine the lighting at the intersection point.

Part 2: Bounding Volume Hierarchy

I used a recursive algorithm to construct the BVH. The base case was that if the distance between the start and end primitive was less than or equal to max_leaf_size, then I return the BVH node with its start and end variables set to the start and end primitive respectively, and the right and left children set to null. If there are still more primitives than max_leaf_size, then I set the axis to split based off which one has the greatest distance between start and end. The heuristic I chose for the splitting point was taking the average of the primitives across the chosen axis. This was done by iterating through all of the primitives from start to end, adding their corresponding axis values, dividing by the number of primitives, and setting it as the split point. Finally, I set the node's left and right pointers by calling construct_bvh(start, splitpoint, max_leaf_size) and construct_bvh(splitpoint, end, max_leaf_size) respectively. To account for infinite recursion, I check to see if the splitpoint is equal to either the start or the end pointer, and if so I reset the splitpoint to \[start + count / 2\].
